# LX Pure 核心金链路回归清单（Golden Path Regression Checklist）

> **目的**：LX Pure 是轻量极简的双端原生音乐播放器，底层播放状态机、自定义源 JS 沙箱、缓存与双端 UI 紧密联动。本清单用于确保**每次新增功能或修复 Bug 时，绝不破坏既有核心功能**。
>
> 每次改动先看「一、模块改动 → 必测回归映射表」，再逐项核对命中的「二、核心金链路（G1–G10）」与「三、破坏性冒烟用例（A1–A5）」。

## 二、10 项核心金链路回归清单（Golden Path）

### G1. 播放 / 暂停 / 进度全端状态同步
- [ ] 全屏播放页、底部迷你播放条（FloatingMiniPlayer）、系统通知栏 / 锁屏控制中心 / 耳机线控四处状态完全一致，无“图标显示暂停但实际在播”或反向不同步。
- [ ] 拖动进度条（Seek）后进度准确跳变、歌词同步定位，不回弹到旧位置。
- [ ] 切歌、暂停、再播放切换干脆，无双击失灵或状态滞后。

### G2. 4 种播放模式与队列导航
- [ ] 顺序播放（`SEQUENTIAL`）：列表播完最后一首严格停止，不错误循环；边界按钮置灰状态准确。
- [ ] 列表循环（`LIST_LOOP`）：末尾下一曲回到首曲，首曲上一曲回到末曲。
- [ ] 随机播放（`SHUFFLE`）：下一曲无短周期重复，上一曲能沿历史栈准确回退。
- [ ] 单曲循环（`SINGLE_LOOP`）：自动播完重播当前曲目；手动点上一曲/下一曲仍可正常切歌。
- [ ] 任意播放进度点击上一曲直接切至上一曲（不再受 5 秒重播阈值限制；仅在顺序播放首曲、随机播放起点或单曲队列等边界时按既定提示重播），预加载目标与实际下一曲一致。

### G3. 自定义源导入、热切换与沙箱隔离
- [ ] 导入合法 `.js` 自定义源（含 CRLF/LF 不同换行符、标准与 `/*!` 头注释）能正确解析元信息与版本徽章。
- [ ] 播放中途或列表页切换自定义源后：旧源在途请求被取消，**不会复用旧源错误缓存**，新源可立即正常解析起播。
- [ ] 禁用/删除当前自定义源后状态优雅降级，不崩溃、不残留死循环请求。

### G4. 音源失效 / 断网 / 卡顿快速失败与恢复
- [ ] 遇到确定性 HTTP 4xx（401/403/404/410/416 等）或音频解析异常时快速失败，不长时间转圈卡死。
- [ ] 音质降级链严格向下（`FLAC24 → FLAC → 320K → 128K`），不出现向上回跳或无限重试。
- [ ] 断网或弱网超时后有清晰错误提示，网络恢复后点击播放可正常恢复。

### G5. 后台保活与冷重启状态恢复
- [ ] 播放中切到后台、息屏锁屏持续播放不中断，系统媒体控制键可正常切歌/暂停。
- [ ] 杀掉 App 进程后重新冷启动：恢复上次播放队列、当前曲目、播放进度与播放模式，且不会破坏旧版持久化数据兼容性。

### G6. 搜索与歌手点击直搜
- [ ] 关键词搜索、聚合结果展示、点击结果起播正常。
- [ ] 全屏播放页点击单歌手直接跳搜索；多歌手（含 `/`、`、`、`feat.` 等分隔格式）弹出选择器且单行溢出排版不乱。
- [ ] 上游返回脏 JSON（字段为 `null`、数组含 `null`、缺失封面/专辑对象）时不崩溃。

### G7. 歌单、收藏与大曲目量体验
- [ ] 自建歌单增删改、上限限制（自建上限 10 个）、从播放页与歌曲菜单添加到歌单（含外部导入歌单）正常。
- [ ] 歌单新增曲目默认置顶，快速定位/直达底部滚动条流畅，不卡顿。
- [ ] 多歌单/大曲目量反复进出不出现明显内存暴涨或重复反序列化卡顿。

### G8. 本地音乐扫描与下载播放
- [ ] 本地音频扫描结果准确入库，离线断网下本地音乐与已下载曲目可正常起播、切歌、读时长/歌手信息。

### G9. 极简 UI 交互与防误触
- [ ] 全屏播放页完全拦截点击与滑动手势，**不穿透触发底层页面元素**。
- [ ] 迷你播放条左右滑动切歌无抖动误触，播放/暂停与上一曲/下一曲点击热区清晰（≥ 44dp/pt）。
- [ ] 弹窗、Toast 与空态样式统一，暗色/流光背景文字对比度清晰。

### G10. 双端一致性与工程纯净红线
- [ ] Android 与 iOS 对应功能行为、默认值、版本号一致（`app/build.gradle.kts` ↔ `ios/project.yml`；双端 `user-api-preload.js` 同步）。
- [ ] 自动化测试全绿：
  - Android：`.\gradlew.bat testDebugUnitTest --no-daemon --max-workers=2`
  - iOS：`ios/LXPureTests/` 同步覆盖并在 macOS CI 跑通 `xcodebuild test`
- [ ] 开源纯净红线：`main` 分支零第三方音源脚本/预设/链接、零签名密钥与本机绝对路径。

## 三、破坏性 / 对抗性冒烟用例（Adversarial Smoke Tests）

每次改动核心模块时，QA 至少执行命中的对抗场景：

- **A1. 狂点切歌竞态**：1 秒内连续快速点击「下一曲 / 上一曲 / 播放暂停」5 次以上，最终播放的音轨、UI 标题封面与通知栏状态必须完全一致，无双声道叠音。
- **A2. 播一半热切源**：歌曲播放 10 秒左右立即去源管理页切换另一个自定义源再切歌，确认不卡死、不误播旧缓存、无后台旧请求报错弹窗。
- **A3. 断网起播与恢复**：开启飞行模式点击未缓存歌曲，确认快速失败不假死；关闭飞行模式后重试可立即播放。
- **A4. 畸形输入压力**：导入含 CRLF 换行 / 缺失头字段 / 语法错误的 `.js` 脚本，以及模拟缺失字段与 `null` 元素的平台 JSON，App 均应安全拦截提示而不崩溃。
- **A5. 大歌单反复切换与冷启**：在包含数百首曲目的歌单中反复添加、置顶、滚动、切歌并冷重启，检查启动耗时与队列恢复准确性。
